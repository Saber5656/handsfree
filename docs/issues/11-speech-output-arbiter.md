# Title

SpeechOutputArbiter: half-duplex gate, priority queue, earcons

## Summary

Implement the `SpeechOutputArbiter` actor that owns all sound output: it
serializes TTS utterances by priority, pauses/resumes STT around playback
(half-duplex), drops stale narration, and plays the earcon set.

## Context

ADR-008 makes this component the correctness guarantee that Handsfree never
transcribes its own voice — which the approval threat model depends on
(DESIGN §9.2 T1/T3: the approval earcon + template announcements flow through
here).

## Scope

- `HandsfreeSpeech/Arbiter/SpeechOutputArbiter.swift`, `Earcons/` player +
  bundled placeholder sounds. Not: what to say (23/21), TTS engine (10).

## Detailed Requirements

1. API (actor):
   ```swift
   func enqueue(_ u: SpokenUtterance)                  // priority queue
   func play(_ earcon: Earcon) async                   // short cue, also gates STT
   func cancelAll(below priority: SpeechPriority)      // e.g. flush narration
   var isOutputActive: Bool
   var sttGate: AsyncStream<Bool>                      // false while any output plays
   ```
   Priorities: `.approval > .result > .narration` (DESIGN §4.4).
2. Half-duplex gating: before starting any output, emit `sttGate=false`;
   after the last queued item finishes (debounce 150 ms so consecutive items
   don't flap the mic), emit `sttGate=true`. The consumer (28) pauses STT
   ingestion on this signal; buffers during the gate are dropped, not queued.
3. Queue rules:
   - `.approval` enqueue: cancel current+queued `.narration` items
     (`.cancelled` events propagate), then play its earcon + utterance next.
   - `.narration` staleness: items older than 10 s at dequeue time are dropped
     silently (DESIGN §4.4); each item carries an enqueue timestamp.
   - `.result` never drops; FIFO within a priority.
4. Earcons: enum
   `sessionStart, sessionEnd, listeningResumed, dispatch, approvalRequest,
   success, failure, deviceChanged` mapped to bundled `.caf` files
   (`Resources/earcons/`). Commit placeholder sounds generated by
   `scripts/gen-earcons.sh` (committed script using `afconvert` on synthesized
   AIFFs — distinct pitches/patterns per earcon; run once, commit the .caf
   outputs). `approvalRequest` must be clearly distinct (longer, two-tone).
5. Playback via `AVAudioPlayer` (output only — must not touch the input
   engine); earcons also hold the STT gate for their duration.
6. Long-narration follow-up: after any output ≥ 5 s, automatically play
   `listeningResumed` when the gate reopens (DESIGN ADR-008 consequence).

## Acceptance Criteria

- [ ] Priority/flush behavior: approval flushes narration (mock TTS records
      cancellation); result survives.
- [ ] Staleness: narration enqueued > 10 s ago (TestClock) is never spoken.
- [ ] Gate signal: exactly one false→true cycle around a burst of 3 queued
      items (debounce verified with TestClock).
- [ ] Earcon assets load from `Bundle.module` in the assembled app (issue 05
      smoke extended) and each enum case has a distinct file.
- [ ] `live` smoke: session-start earcon + one sentence + listening-resumed
      earcon audible in order.

`live` run note in PR.
